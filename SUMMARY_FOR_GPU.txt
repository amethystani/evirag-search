QUICK START (on your 48GB Ada 4500 machine)
================================================================================

1. Clone the repo:
   git clone https://github.com/amethystani/evirag-search.git
   cd evirag-search

2. Set HF token (to upload results):
   export HF_TOKEN=your_hf_token_here

3. Run the pipeline (sequentially):
   cd pipeline
   pip install -r requirements.txt

   python3 1_download_corpus.py        # ~5-8 hrs
   python3 2_embed_and_quantize.py     # ~4-6 hrs (GPU speeds this up 10x)
   python3 3_build_faiss_index.py      # ~15-20 min
   python3 4_upload_to_hf.py           # ~30-60 min

Total time: ~10-15 hours (mostly parallelizable, GPU-accelerated)

================================================================================
WHAT EACH STEP DOES
================================================================================

STEP 1: DOWNLOAD CORPUS (~5-8 hrs)
  Input:  OpenAlex API (free, no auth needed)
  Output: ./raw_corpus/batch_0000.parquet ... batch_0200.parquet
  Action: Cursor-based pagination for 40-50M scientific papers
  Filters: has_abstract=true, cited_by_count>5, lang=en, 2000-2025
  Resume: Saves cursor.txt — if it crashes, just re-run
  GPU:    Not used (network-bound)

STEP 2: EMBED & QUANTIZE (~4-6 hrs on Ada, ~2 days on CPU)
  Input:  ./raw_corpus/batch_*.parquet (40M+ papers)
  Output: ./embeddings/
           - ids.npy           (OpenAlex IDs)
           - binary.npy        (40M × 96 bytes, binary vectors)
           - metadata.parquet  (title, year, doi, citations, source)
  Action:
    1. Load abstracts from Parquet batches
    2. Embed with SPECTER2 (768-dim, scientific papers, GPU-accelerated)
    3. Normalize embeddings to unit sphere
    4. Binary quantize: sign(embedding) → 1 bit per dim → 96 bytes/vector
    5. Save checkpoints every 5 batches (resumable)
  GPU:    ~30-35GB VRAM peak (safe on 48GB Ada)
  Speed:  Ada 4500 does 40M vectors in 4-6 hrs
          CPU does same in 2 days
          10-15x speedup — worth running on GPU

STEP 3: BUILD INDEX (~15-20 min)
  Input:  ./embeddings/binary.npy
  Output: ./embeddings/evirag.index (~4GB)
  Action:
    1. Load binary vectors (memory-mapped, doesn't use full RAM)
    2. Build FAISS IndexBinaryIVF with 8192 clusters
    3. Train on 2M random vectors
    4. Add all 40M vectors in batches
    5. Save ready-to-query index
  Query latency: 10-20ms for top-100 on CPU
  GPU:    Not used (FAISS training is CPU-optimized, stays on CPU)

STEP 4: UPLOAD (~30-60 min)
  Input:  ./embeddings/evirag.index, ids.npy, metadata.parquet (~6GB total)
  Output: https://huggingface.co/datasets/amethystani/evirag-index
  Action:
    1. Create/verify HF Dataset repo
    2. Upload all 3 files
    3. Files now live on HF (public, CDN-distributed)
  GPU:    Not used (network-bound)
  Note:   The HF Space backend downloads these files on first boot

================================================================================
AFTER STEP 4: THE SPACE GOES LIVE
================================================================================

Once uploads complete:
  1. HF Space (https://huggingface.co/spaces/amethystani/evirag-search)
     auto-downloads the index on next boot
  2. Queries stream into /search endpoint

================================================================================
TROUBLESHOOTING
================================================================================

Step 1 crashes?
  → Re-run. It saves cursor.txt and resumes from last position.

Step 2 runs slowly (less than 100 vectors/sec)?
  → Check: nvidia-smi (verify GPU is being used)
  → Lower BATCH_SIZE in 2_embed_and_quantize.py if OOM

Step 2 OOM despite 48GB?
  → Reduce BATCH_SIZE from 512 → 256 or lower
  → The script checkpoints every 5 files, so OOM can resume

Step 4 upload times out?
  → Your HF token might be invalid
  → Check: export HF_TOKEN=your_real_token
  → Or re-run: HF_TOKEN=xyz python3 4_upload_to_hf.py
